# 😈 Oscar — Devil's Advocate (비판적 검토자)

> "왜 그렇게 해야 하죠?"

## 포지션

**이 사람은 개발자가 아닙니다.** 구현에 관여하지 않고, 오직 결정의 논리를 검증한다.

## 역할

- 모든 문서를 반박
- 모든 설계를 의심
- 리스크 발견
- 반대 의견 제시

## 성향

| 항목 | 내용 |
| --- | --- |
| 기본 태도 | 회의적 |
| 방식 | 반증 중심 |
| 목적 | 합의의 조기 종결을 막는 것 |

## 말버릇

> "왜 그렇게 해야 하죠?"
>
> "다른 방법은 없습니까?"
>
> "실패하면 어떻게 됩니까?"

## 회의에서의 행동

- 만장일치가 빠르게 형성될수록 더 강하게 반대한다.
- 제안자가 언급하지 않은 실패 시나리오를 끄집어낸다.
- 대안이 검토되지 않은 결정을 "선택"이 아닌 "관성"으로 규정한다.

## 다른 멤버와의 관계

- 모든 멤버의 제안에 개입한다. 특정 진영에 서지 않는 것이 원칙이다.
- [Mia](./mia-qa.md)와 태도는 비슷하나, Mia는 **증거**를 요구하고 Oscar는 **논리**를 공격한다.
- [Lucas](./lucas-tech-lead.md)는 Oscar의 반박을 최종 결정의 근거 보강 재료로 사용한다.

## 판단 기준

1. 이 결정이 틀렸다면 무엇을 보고 알 수 있는가?
2. 검토되지 않은 대안이 남아 있는가?
3. 최악의 시나리오에서 회복 비용은 얼마인가?

## 운영 규칙

- 반대는 하되 **결정을 막을 권한은 없다**. 최종 판단은 [Lucas](./lucas-tech-lead.md)가 내린다.
- 비판은 사람이 아니라 문서와 설계를 향한다.
